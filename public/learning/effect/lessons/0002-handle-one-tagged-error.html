Effect v4 beta.103 · Lesson 0002 · 15 minutes

Make one expected error disappear.

Recover StaticAssetFetchError inside the Effect program so the Worker boundary receives an Effect whose expected-error channel is never.

Tangible win

When the Cloudflare assets binding rejects, the blog will return a security-header-protected 500 response instead of rejecting the Worker request.

1. Start with a failing behavior test

In src/app.test.ts, add a test whose asset binding returns Promise.reject(cause). Call blogHandler.fetch and require all three outcomes:

  • the Promise resolves rather than rejects;
  • the response status is 500 and its body is Internal Server Error;
  • the response still has X-Content-Type-Options: nosniff.
pnpm exec vitest run src/app.test.ts

Your new test should fail first. That red test is the feedback loop for the production edit.

2. Notice the discriminator you already have

class StaticAssetFetchError extends Error {
  readonly _tag = "StaticAssetFetchError"
}

Effect’s catchTag selects recoverable errors through this readonly _tag. The official v4 migration guide confirms that catchTag is unchanged in v4.

Effect<Response,
StaticAssetFetchError>
→ catchTag →
Effect<Response,
never>
Prediction check

If StaticAssetFetchError is the only member of E, and its recovery handler cannot fail, what is the resulting error type?

3. Change the production pipeline

Work only in the static-assets branch of src/app.ts. Keep fetchStaticAsset unchanged. Your final pipeline must:

  1. start from fetchStaticAsset(request, env, url);
  2. recover only StaticAssetFetchError using Effect.catchTag;
  3. log the error and produce the 500 response inside an Effect.sync handler;
  4. apply withSecurityHeaders to both normal and recovered responses;
  5. call Effect.runPromise only after recovery and header mapping.

Add the annotation const program: Effect.Effect<Response>. Because omitted E and R default to never, TypeScript will reject an incomplete recovery.

Progressive hints

Hint 1 — pipeline order

Recover first, then map withSecurityHeaders. That single map will cover both the asset response and the fallback response.

Hint 2 — catchTag shape
Effect.catchTag("StaticAssetFetchError", (error) =>
  Effect.sync(() => {
    // log, then return a Response
  })
)
Hint 3 — complete pipeline skeleton
const program: Effect.Effect<Response> = fetchStaticAsset(...).pipe(
  Effect.catchTag(/* tag */, /* recovery */),
  Effect.map(/* apply headers */),
)

return Effect.runPromise(program)
Final reveal — compare only after attempting it
const program: Effect.Effect<Response> = fetchStaticAsset(request, env, url).pipe(
  Effect.catchTag("StaticAssetFetchError", (error) =>
    Effect.sync(() => {
      console.error(error);
      return new Response("Internal Server Error", { status: 500 });
    })
  ),
  Effect.map(withSecurityHeaders),
);

return Effect.runPromise(program);

4. Close the loop

pnpm exec vitest run src/app.test.ts
pnpm run typecheck

Then run the full test suite. Do not move runPromise further yet; the rest of request routing is not an Effect program, so the current branch remains a deliberate migration seam.
