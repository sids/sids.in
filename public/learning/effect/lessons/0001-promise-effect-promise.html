Effect migration · Lesson 0001 · 10 minutes

Cross the boundary once.

Turn one existing Promise operation into a lazy Effect with a typed failure, then hand a Promise back to the unchanged Worker.

Tangible win

The static asset binding can reject. That failure is now visible in the program’s type as StaticAssetFetchError, while the Worker’s public fetch boundary still returns a Promise.

1. Read the type as a sentence

Effect.Effect<Response, StaticAssetFetchError, never>
Responsesucceeds with
StaticAssetFetchErrorcan fail with
neverrequires no services

A Promise exposes only its success value in Promise<Response>. Effect gives expected errors and required services their own type channels. This three-part interpretation comes directly from the official Effect type documentation.

2. Enter Effect at the leaf

Open src/lib/static-assets.ts. The existing Cloudflare binding still returns a Promise; tryPromise describes that operation and maps a rejection into our domain-specific error.

return Effect.tryPromise({
  try: () => env.ASSETS.fetch(request),
  catch: (cause) => new StaticAssetFetchError(cause),
}).pipe(
  Effect.map((response) => /* add immutable cache headers */),
)

tryPromise is used because the underlying Promise may reject. The official constructor docs distinguish it from Effect.promise, which does not model rejection in the error channel.

Prediction check

Immediately after calling fetchStaticAsset(...), how many times has env.ASSETS.fetch run?

3. Exit Effect at the existing boundary

src/app.ts is still a Promise-based Cloudflare handler. One runner executes the program there:

await Effect.runPromise(fetchStaticAsset(request, env, url))

This is the incremental adoption seam: Promise API → Effect program → Promise caller. The runner docs describe runPromise specifically as the compatibility tool for Promise-based code.

4. Run the feedback loop

pnpm exec vitest run src/lib/static-assets.test.ts

The first test proves laziness: the fetch count remains zero until runPromise. The second uses Effect.flip to inspect the typed error as a success value.
