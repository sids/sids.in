Effect<A, E, R>

Effect v4 beta.103 · the three-channel type and incremental migration boundary.

A — Success
The value produced when the program succeeds.
E — Error
The expected failures callers must consider.
R — Requirements
The services the program needs. No requirements is never.

Promise API→Effect.tryPromise→Effect program→Effect.runPromise→Promise caller
OperationPurposeRule of thumb
Effect.tryPromiseDescribe a rejecting Promise as an Effect and map unknown into a typed error.Use for existing async APIs that may reject.
Effect.mapTransform the success value without changing the error channel.Like mapping the resolved value, but still lazy.
Effect.runPromiseExecute an Effect and expose a Promise.Keep runners at application or compatibility boundaries.
Effect.flipSwap success and error channels.Handy in a focused test of a failure value.

Key distinction: constructing an Effect describes work; a runtime function executes it.
